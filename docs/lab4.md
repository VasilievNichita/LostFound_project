# Состояние и хранилища LostFound

Item, Claim и Message вынесены из seed-файла в entities.dart. Поля неизменяемые; copyWith создаёт новую версию объекта. Экраны получают данные от LostFoundModel. В модели хранятся коллекции, фильтры доски, загрузка и ошибка. Контроллеры форм и переключатель сбоя остаются локальными. Нижними вкладками по-прежнему управляет go_router.

Модель получает ItemRepository, ClaimRepository и MessageRepository через конструктор. Это три обычных интерфейса, без универсального ORM или генераторов. Item и Claim поддерживают CRUD, Message поддерживает список, создание и удаление по контракту темы. Ответ каждого метода имеет тип Future<Result<T>>. Success содержит данные, Failure содержит понятное сообщение. UI показывает loading, данные или ErrorView с повтором.

MockStore связывает три хранилища и содержит единственный импорт mock_data.dart. Каждая операция ждёт 650 мс. simulateError заставляет любой запрос вернуть Failure до изменения коллекций. ID создаёт хранилище, входной ID новой сущности игнорируется. После полного перезапуска создаётся новый seed, файловая БД здесь не используется.

Новая вещь увеличивает счётчик в нижней панели, разделе «Мои» и профиле. Поиск и место сохраняются при переходах, поэтому новая вещь может не подходить текущему фильтру. Закрытие помечает вещь как возвращённую и запрещает новые сообщения. Удаление своей вещи очищает связанные заявки и переписки. Заявку можно удалить из раздела «Мои», своё сообщение удержанием в переписке. Свайп своей публикации влево вызывает подтверждение. При отказе запись остаётся на месте.

В открытой заявке нельзя повторно обратиться на ту же вещь. Закрытая заявка не мешает новому обращению, если сама вещь ещё открыта. Связь по claimId предотвращает смешивание переписок. На L5 эти правила нужно повторить на сервере: проверки локального mock не обеспечивают безопасность backend.

Во время записи кнопки блокируются и виден индикатор. Повторный запрос записи и обновление списка не могут затереть ожидающий результат. Успех применяется к общей модели и извещает подписчиков; ошибка не меняет данные и не очищает поля формы. Объект модели, уже удалённый из дерева, не отправляет уведомления после завершения запроса.

Сценарий Android: `flutter drive --driver=test_driver/integration_test.dart --target=integration_test/lab4_test.dart -d emulator-5554`. Снимки сохраняются в build/lab4-screenshots или в LOSTFOUND_SCREENSHOTS. Тесты L3 для маршрутов и валидаторов сохранены; прежний сценарий «данные не изменяются» заменён сценарием L4.

Просмотрен приложенный Python/FastAPI backend: SQLite, JWT, файлы и CRUD notes с пагинацией. В L4 его код не переносился. Для L5 понадобятся таблицы items, claims, messages с внешними ключами, серверными датами и правами участников. HTTP-реализации этих интерфейсов будут разбирать ответы API; их подключение меняется в main.dart. Демонстрационный переключатель сбоя тогда удаляется. Аутентификация и фото потребуют функциональных дополнений по заданию L5.

Стандартный механизм Provider использован по документации https://pub.dev/packages/provider. Требования взяты из L4_State_si_Repository_RU.pdf; пример корзины пластинок не переносился. Конкретные правила связей и ошибок относятся к теме LostFound.
